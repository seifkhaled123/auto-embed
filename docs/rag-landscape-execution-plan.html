Product boundary

Files in. Retrieval-ready data out.

The right competitive position from the landscape report is retained: “the zero-config, production-grade ingestion and indexing CLI for RAG.” Work is admitted only when it improves local-file acquisition, parsing, chunking, embedding, index writes, idempotency, or evidence about those stages.

Inside the tool

Deterministic local-file ingestion and the safeguards needed to make it dependable in development and CI.

  • Resolve local file paths, quoted globs, and directories.
  • Parse supported text-bearing files with safe fallbacks.
  • Chunk, embed, cache job progress, and upsert reliably.
  • Export vectors and preserve source/chunk provenance.
  • Benchmark ingestion choices without exposing a query product.

Outside the tool

The online application path remains owned by the user’s vector database SDK, orchestration framework, or a future sibling package.

  • Query APIs, top-k search, hybrid fusion, and reranking.
  • Prompt construction, citations, answer generation, and chat memory.
  • Agentic routing, GraphRAG, and tool orchestration.
  • Hosted scheduling, worker fleets, dashboards, tenancy, and authorization enforcement.
  • Online answer evaluation and production feedback collection.

Execution sequence

Four gated releases.

Work is sequential, matching the repository rule to complete one milestone before starting the next. Each release begins with tests for the promised behavior and ends with typecheck, tests, build, circular-dependency check, and a built-CLI smoke test.

R1

Contract repair

Make every advertised local-input and inspection behavior true before widening capability.

  • Add a command-layer input resolver for explicit files, quoted globs, and recursive directory arguments; normalize, deduplicate, and sort paths deterministically.
  • Honor repository-safe default ignores for .git, node_modules, .auto-embed, generated output, and symlink recursion; explicit file arguments still win.
  • Define unmatched-pattern behavior as one typed user/config error with an actionable hint.
  • Implement content sniffing and safe text fallback; keep malformed supported formats as parser errors rather than silently treating them as plain text.
  • Implement --out-vectors as ordered JSONL containing source, chunk ID/text/metadata, model, dimensions, and vector—never credentials or config.
  • Add built-CLI contract tests for every public input/preview flag and invalid combination; update PRD, PLAN, README, and help text together.
Release gate

Quoted globs and directories work cross-platform; duplicate matches ingest once; empty matches fail predictably; unknown text falls back with a warning; binary content fails; multi-file vector export is deterministic and atomic.

bun run typecheck && bun run test && bun run build
R2

Crash-safe ingestion

Turn idempotency from a final lockfile optimization into durable batch-level recovery.

  • Create an atomic JSON job manifest under .auto-embed/jobs/, keyed deterministically by source hash, plan hash, provider/model, database, and collection.
  • Refactor embedding execution to commit each completed batch to the vector store, then checkpoint its chunk IDs; never checkpoint vectors that were not successfully upserted.
  • On retry, skip committed batch IDs, process the remainder, apply removals only after all replacement upserts succeed, then atomically write the final lockfile.
  • Keep incomplete manifests for recovery; remove or mark them complete only after the lockfile commits. --force starts a new deterministic job generation.
  • Wrap every resolved database lifecycle in try/finally; verify cleanup on dimension failures, provider errors, DB errors, and interrupts.
  • Add failure-injection tests at embed, upsert, delete, lockfile-write, and close boundaries with zero real provider traffic.
Release gate

A forced failure after batch N causes the next run to begin at N+1; completed vectors are not paid for twice; removed chunks remain available until replacements are safe; DB close is observed on every exit path.

bun run test test/engine.test.ts test/pipeline.test.ts test/lockfile.test.ts
R3

Bounded large-file path

Meet the >100 MB promise where formats permit streaming, and fail transparently where third-party parsers do not.

  • Replace whole-file hashing with createReadStream-based hashing.
  • Introduce a parser-section async-iterator contract without leaking provider or DB concerns into parser/chunker layers.
  • Stream line/record-oriented TXT, CSV, JSONL, logs, and code; preserve deterministic section order, chunk IDs, overlap semantics, and metadata.
  • Feed batches forward without retaining every embedding vector in memory; retain only the chunk identity/metadata required for the lockfile.
  • Measure Markdown, HTML, DOCX, JSON, and PDF libraries; define documented per-format limits and actionable errors for unavoidable whole-document paths.
  • Add generated 128 MB smoke fixtures outside git and record peak RSS, wall time, and cleanup behavior in an opt-in performance test.
Release gate

A generated 128 MB TXT and JSONL corpus completes without readFile in parser/hash paths, preserves repeatable chunk IDs across two runs, and stays below a ratified memory ceiling recorded in CI artifacts.

bun run test && bun run build && bun run perf:large
R4

Quality evidence & release hardening

Create a reproducible answer to “did this ingestion change improve retrieval?” without adding retrieval to the product surface.

  • Add a private, opt-in benchmark runner under engineering scripts—not a public auto-embed query command.
  • Version small representative corpora, questions, relevant chunk/source labels, and hard negatives; avoid copyrighted or sensitive data.
  • Measure Hit Rate, Recall@K, Precision@K, MRR, and nDCG for chunk size, overlap, splitter, model, and parser variants using a documented local evaluation backend.
  • Save machine-readable experiment manifests and an HTML/JSON comparison report; establish the current structural chunkers as the baseline.
  • Add regression thresholds only after repeated runs establish stable variance; keep network/provider evaluation opt-in.
  • Run cross-platform built-CLI smoke tests, package-size/cold-start checks, madge --circular, docs reconciliation, and release notes.
Release gate

The same manifest reproduces the same corpus/chunk identities and metric report; the baseline is published with limitations; no query, rerank, or generation API appears in the CLI bundle.

bun run eval && bun run typecheck && bun run test && bun run build

Required by project conventions

Hard exclusions

Not in this tool.

These report gaps are real capabilities in a complete RAG system, but they are not deficiencies auto-embed should absorb. Some may become a sibling package; others belong to application code or managed infrastructure.

Retrieval runtime

No query embedding, top-k, filters, hybrid fusion, MMR, rewrites, HyDE, routing, parent expansion, or GraphRAG. Use the vector DB SDK or a separate retrieval package.

Rerank & compose

No cross-encoders, context compression, prompt-budget packing, snippet selection, or citation rendering. These are query-time concerns.

Generation & agents

No grounded-answer runtime, prompt registry, structured answers, chat memory, agent loops, or tool routing. auto-embed produces an index; it does not answer.

Hosted synchronization

No cron service, filesystem watcher, webhooks, CDC, remote cursors, durable queues, worker fleet, or control dashboard. The CLI remains one-shot and CI-friendly.

Authorization enforcement

Future ingestion may preserve ACL-like metadata, but this tool cannot guarantee query-time authorization, tenant isolation, quotas, or audit access. Enforcement lives in the serving layer.

Online evaluation

No answer judges, production traces across an LLM app, thumbs feedback, failed-search queues, or citation-click analytics. R4 evaluates offline ingestion choices only.

Database-row ingestion

No SQL, MongoDB, Snowflake, Kafka, REST, GraphQL, or stream records. The PRD reserves this for a future auto-embed db concept.

Web crawling

No URL loader, sitemap, RSS, recursive crawler, or browser automation. Current scope remains local files; downloaded HTML is supported.

Multimodal indexing

No image, audio, video, page-image, ColPali, ColBERT, or VLM vector path. The current provider/store contracts remain dense text vectors.

Approval gate

Review. Tweak. Then execute.

Approval authorizes only R1 first. R2 starts after R1 acceptance is green; the same rule applies to R3 and R4. Deferred items require a new PRD decision and a separate plan, even if they appear in the landscape report as P0 or P1.
