01 / USER EXPERIENCE

One command meets a real repository.

The CLI surface now matches how documentation actually lives: individual files, shell-safe quoted globs, and whole directories. Resolution is predictable, duplicate-safe, and explicit about content it cannot trust.

INPUTS / RESOLVE

Files, globs, directories

Pass any combination. Results are normalized, de-duplicated, and sorted before work begins, so a file matched twice is ingested once.

auto-embed embed ./docs "./runbooks/**/*.md"
INPUTS / SAFETY

Repository-aware recursion

Directory walks skip .git, node_modules, .auto-embed, dist, and chroma. Symlinked directories are not followed; an explicitly named file still wins.

PARSING / TRUST

Sniff, then decide

An unfamiliar extension containing text falls back with a warning. Binary content fails clearly. A malformed known format remains an error instead of silently becoming garbage text.

INSPECTION / OUTPUT

See chunks or keep vectors

--show-chunks stops before providers and databases. --out-vectors creates one ordered JSONL containing source, text, metadata, model, dimensions, and vector, then atomically renames it only after success.

--out-vectors ./artifacts/docs-vectors.jsonl
RECOVERY / RESUME

Continue after the last safe batch

Completed upserts are checkpointed. A retry skips paid-for batches, finishes replacements, delays old-vector deletion until safety, writes the final lockfile, and clears the job manifest.

CONTROL / INTERRUPTS

Stop without corrupting progress

SIGINT and SIGTERM stop new work, allow active calls to settle, close the database, and leave a resumable manifest. --force intentionally starts fresh.

02 / SAFE JOURNEY

Commit work in the right order.

The happy path and recovery path now share the same promise: a checkpoint describes only vectors the database has accepted, and obsolete vectors survive until their replacements are safe.

1

Resolve

Expand and sort every explicit path, glob match, and directory descendant.

2

Stream

Hash, parse, and chunk in stable source order with format-aware boundaries.

3

Upsert

Embed concurrent batches while committing database writes serially.

4

Checkpoint

Record a batch only after its upsert succeeds; retries skip those IDs.

5

Finalize

Delete superseded IDs, atomically write the lockfile, then remove job state.

05 / PRODUCT BOUNDARY

Stronger focus, not broader sprawl.

The release deepens the path from local file to trustworthy dense-vector index. Everything after retrieval begins remains the serving application’s job.

Inside auto-embed

  • Local file discovery and parsing
  • Token-aware structural chunking
  • Embedding provider batches
  • Vector database upserts and safe replacement
  • Idempotency, recovery, previews, and exports
  • Private offline ingestion evaluation

Deliberately outside

  • Public query or retrieval runtime
  • Hybrid search, MMR, reranking, or HyDE
  • Prompt composition, generation, citations, or agents
  • Hosted watchers, queues, dashboards, or synchronization
  • Query-time authorization and tenant enforcement
  • Web crawling, database ingestion, or multimodal vectors
